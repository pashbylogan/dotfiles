Architecture

A thin overlay, not a convergence engine

Omarchy is an opinionated distro: it installs ~150 base packages and seeds every config on first boot. This repo therefore carries only deltas — the owner's intentional customizations — and leans on Omarchy's own tools to apply them.

The one rule D-DELTA-STORAGE

Never symlink an Omarchy-owned mutable file into git. Own a thin personal fragment, and integrate it with a single managed block appended to Omarchy's file. Omarchy keeps owning (and updating/migrating) its own files; we keep owning ours.

Why this matters: Omarchy resets configs with cp -r/cp -f (e.g. omarchy-nvim-setup, omarchy-refresh-config). If a destination were a symlink into our repo, that copy would write through the symlink and silently mutate the git-tracked source. Backups exist, but they'd back up our repo file. Owning whole seeded files also freezes them — we'd miss Omarchy's upstream improvements. See Findings for the evidence.

Ownership model

Owner Responsible for
Omarchy Package-backed platform under /usr/share/omarchy; the mutable Hyprland entry point and Quickshell shell.json; terminal/browser integration; the separate omarchy-nvim tree; coding-agent mise wrappers; migrations, themes, and package/system updates.
This repo Personal overlays only: a reloadable Hyprland Lua module, Quickshell plugin/command/theme deltas, bash additions, ssh config, personal commands, nvim keymap/plugin/extras deltas, and explicit package additions/removals — plus repo hygiene (a Makefile + CI that lint/format the scripts and verify docs integrity, see D-CI).

Integration-block mechanism

Where we must touch an Omarchy-owned file, install uses one helper, upsert_block, that removes any prior managed block, then appends one canonical block at end-of-file: 

# >>> dotfiles >>>
... our lines ...
# <<< dotfiles <<<

A presence-only "grep and append if missing" guard is rejected: in both Hyprland and bash, load order decides who wins. Re-anchoring the block at EOF on every run guarantees (a) exactly one block — idempotency — and (b) that our overlay is sourced last, so it overrides Omarchy defaults.

Applied to five files:

Omarchy-owned file Managed block does
~/.bashrc sources ~/.config/dotfiles/shell.sh (+ shell.local.sh)
~/.config/hypr/hyprland.lua requires reloadable hypr.dotfiles and the optional hypr.dotfiles_local module
~/.config/nvim/lua/config/keymaps.lua dofiles the tracked ~/.config/dotfiles/nvim.lua fragment (personal keymaps + options)
~/.config/tmux/tmux.conf source-file ~/.config/tmux/local.conf (omarchy ships this file and tmux prefers it over ~/.tmux.conf, so we overlay it)
~/.config/starship.toml references and configures starship's built-in python module

Quickshell's shell.json has no deep merge, so it uses a different mechanism: install drives Quattro's own omarchy bar / omarchy plugin CLI, which routes through the same omarchy-shell-config normalize, atomic commit, and reload path. The plugin is a user-owned extension file; mutable shell.toml receives no TOML delta and the layout stays unstowed. See D-QUICKSHELL-DELTAS.

Neovim adds two more managed seams beyond the keymaps block, because lazy.nvim plugin specs must exist before lazy.setup(): install writes a generated loader to ~/.config/nvim/lua/plugins/dotfiles.lua (returning the tracked ~/.config/dotfiles/nvim-plugins.lua spec fragment) — guarded on the seeded dir, since pre-creating the tree would stop omarchy-nvim-setup from ever seeding — and applies a jq delta (nvim/lazyvim.jq) onto LazyVim-rewritten lazyvim.json, touching only .extras. See D-NVIM-KEYMAPS.

What stow does (and doesn't)

Stow only places repo-owned static files at paths Omarchy doesn't seed — our own namespaces (~/.config/dotfiles/, ~/.ssh/, ~/.local/bin/, ~/.config/tmux/local.conf) and Omarchy extension points reserved for user content (the Hypr Lua module and Quickshell plugins/scripts). Stow never symlinks an Omarchy-managed mutable file.

Idempotency guarantee D-IDEMPOTENT

install converges to the same state on any number of runs:

  • omarchy pkg add → no-op when installed (pacman --needed).
  • omarchy pkg drop via D-PKG-REMOVE → filters to installed-only before pacman -Rns, so listing an already-absent name is a no-op. The package surface is now additive + subtractive (packages.txt / packages.aur.txt / packages.remove.txt); other overlay surfaces remain additive-only.
  • stow -R → restow; already-correct links are no-ops; one first-run edge case is a pre-existing real ~/.ssh/config (backed up once, then linked).
  • upsert_block → always exactly one block, anchored last.
  • hyprctl reload → naturally idempotent.

Forward compatibility

The Lua namespace is part of the contract Quattro purges cached modules only under selected prefixes during a reload. The personal module is deliberately named hypr.dotfiles, so it reruns after defaults on every reload; dotfiles.hypr would remain cached and silently stop reapplying. The installer reasserts the small mutable entry-point seam after every refresh.
