  • Dev-env reconciliation: ./install now actively replaces the main off-path install vector (pacman) for the tools this repo owns. The ensure_dev_env_tool helper: omarchy pkg drop $tool when pacman owns it, then omarchy install dev-env <kind> if the tool isn't on PATH. waybar Personal waybar deltas split across two coupled overlays: jq filters in waybar/deltas.jq for config.jsonc (applied by install's apply_jq_deltas helper) and a managed block in style.css (via the existing upsert_block helper) for the matching CSS. waybar restarts only when content actually changed (hash-compare around both files) and the restart polls pgrep -x waybar to verify the process came back. New decision / finding pair documents the pattern and the omarchy mutation surface that makes a delta overlay safer than either a fork or a direct edit: D-WAYBAR-DELTAS, F-WAYBAR-MIGRATIONS. Initial deltas: drop the 1-5 persistent-workspaces pin so workspaces grow i3-style; add an icon-only memory module (glyph  nf-fa-bars, after cpu, on a 5 s interval) with used/total/% in tooltip-format on hover; extend omarchy's #cpu, #battery, ... It worked in the user's interactive bash (where mise activate dynamically PATH-injects that dir) but was invisible to non-interactive shells — forcing a manual PATH prepend for every agent/CI-style make ci. future AppImage application pattern When a needed desktop app has no supported Omarchy, official-repo, AUR, or Flatpak route Treat an AppImage as an explicit application decision, not a hand-managed .desktop file. Prefer native-AUR gearlever for integration only: it owns the menu entry and icon, while normal AUR updates maintain Gear Lever itself. Keep the image unextracted unless the candidate is proven compatible with extraction, then evaluate its updater before enabling any second updater:
  • Check for vendor self-updating, standard AppImage .upd_info, and the expected update trigger. Preserve a normal APPIMAGE launch environment when the vendor updater needs it.
  • Do not assume Gear Lever can provide background updates. The installed Omarchy portal backends do not expose the XDG Background portal, and its background setting checks/notifies rather than silently installing updates.
  • Avoid a generic automatic-update/extraction manager when it would duplicate a working vendor updater. AppImageLauncher v3 remains beta and appimaged is deprecated; AppManager needs a separate candidate-specific evaluation.
  • Record vendor provenance, update behavior, desktop launch flags, and security review before adoption. If accepted, add gearlever to packages.aur.txt and document the resulting managed behavior through the normal decision/finding flow.
Initial candidate: Traycer Desktop. Its current official AppImage has no standard .upd_info, but its Electron updater checks on launch/resume and requires a user-confirmed download and restart. Its vendor desktop entry uses --no-sandbox; review that risk and the vendor updater-credential exposure before installation (no credential is recorded in this repo). Sources: Traycer install, Gear Lever, electron-builder updates, and AppImage updates.
